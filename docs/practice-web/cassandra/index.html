Laboratorio de modelado Cassandra

Diseña las claves de las tablas de una aplicación de preguntas y respuestas con datos reales de Stack Overflow en español, y observa en qué nodo acaba cada fila y qué nodos toca cada consulta.

El problema: el diseño empieza por las consultas

En SQL se diseñan las tablas a partir de las entidades, Users y Posts, y el optimizador resuelve después cualquier consulta, aunque nadie la previera. Cassandra reparte cada tabla entre los nodos del clúster según su clave de partición: el coordinador calcula el token de esa clave y sabe qué nodo guarda la partición. Sólo es eficiente la consulta que conoce la clave. Todas las demás tienen que preguntar a todos los nodos.

Por eso primero se enumeran las consultas de la aplicación y después se elige, para cada una, una clave que le permita leer una partición en un nodo. Dentro de la partición, las columnas de clustering fijan el orden de las filas.

Cuatro salidas cuando la clave no sirve para una consulta

  • ALLOW FILTERING. Pregunta a todos los nodos y lee todas las filas para descartar la mayoría. El coste crece con la tabla, no con el resultado.
  • Índice secundario (SAI). Cada nodo indexa sólo sus filas: es un índice local. Sigue preguntando a todos los nodos, pero cada uno lee sólo lo que coincide.
  • Otra tabla con otra clave. Copia los datos organizados para esa consulta. Lee un nodo, a cambio de más espacio y más escrituras.
  • Índice global. Una tabla pequeña que va del valor buscado a la clave de la fila original. Son dos lecturas de un nodo y la aplicación mantiene la copia.
Qué simula este laboratorio y qué no
  • Un clúster de cuatro nodos con factor de replicación 1: cada partición vive en un único nodo. El anillo de tokens se divide en cuatro rangos iguales.
  • El token es un hash didáctico de 32 bits, no el Murmur3 de 64 bits de Cassandra: los nodos concretos no coincidirán con un clúster real, pero sí el principio.
  • Las cifras de nodos contactados, particiones y filas examinadas describen el trabajo del simulador, no tiempos medidos. No hay réplicas, consistencia, latencia, SSTables, TTL, contadores ni colecciones.
  • CQL disponible: CREATE TABLE, DROP TABLE, CREATE INDEX … USING 'sai', DROP INDEX, INSERT con upsert y SELECT con igualdad, intervalos, LIMIT y ALLOW FILTERING. Tipos int, bigint, text, boolean y timestamp. Lo que quede fuera se rechaza como «No implementado en este simulador».
  • Los boletines de las sesiones 5 y 6 usan Cassandra real; este laboratorio sirve para razonar el diseño antes.

Los datos

Muestra mínima

Preguntas de 2016 de la muestra reducida de Stack Overflow en español, Posts-sample y Users-sample de dsevilla/bd2-data, que conserva una pregunta de cada ocho. Mientras se descargan, o si falla la red, se usa una muestra mínima incrustada con las del primer trimestre.

Columnas que el laboratorio sabe rellenar

Al crear una tabla, el laboratorio la puebla en el acto con las preguntas, usando las columnas cuyo nombre y tipo coinciden con esta lista, igual que el cargador de un cuaderno. Si la tabla tiene la columna etiqueta, escribe una fila por cada etiqueta de la pregunta. Una fila con NULL en la clave primaria no se puede escribir y se omite.
