Ejercicios de las sesiones 1 y 2 con Stack Overflow en español. Escribe una consulta y examínala aquí mismo: DuckDB-Wasm se ejecuta en este navegador.

Cómo se prepara la base de datos

Al abrir esta práctica, DuckDB-Wasm se inicia en tu navegador y carga automáticamente los Parquet desde GitHub. Para formar la tabla Posts, une sus tres fragmentos con read_parquet y materializa el resultado con CREATE TABLE … AS SELECT …:

CREATE TABLE Posts AS
SELECT * FROM read_parquet([
  'https://raw.githubusercontent.com/dsevilla/bd2-data/main/es.stackoverflow/parquet/Posts1.parquet',
  'https://raw.githubusercontent.com/dsevilla/bd2-data/main/es.stackoverflow/parquet/Posts2.parquet',
  'https://raw.githubusercontent.com/dsevilla/bd2-data/main/es.stackoverflow/parquet/Posts3.parquet'
]);

La aplicación repite esa operación para las cinco tablas. Una vez cargadas, los ejercicios consultan Posts, Users, Tags, Comments y Votes dentro de DuckDB; cada consulta SQL usa esas tablas y no vuelve a leer ni descargar los Parquet. Se conservan en la memoria del navegador durante esta sesión: si recargas la página o eliges otra base, hay que cargarlos otra vez.

Preparando DuckDB-Wasm…

DuckDB consulta directamente los Parquet alojados en dsevilla/bd2-data. También puedes seleccionar copias locales de Posts, Users, Tags, Comments y Votes. La muestra pequeña permite probar los ejercicios si falla el acceso remoto.

Los resultados se muestran en bloques de 100 filas; ejecuta una sentencia cada vez. Puedes retroceder en consultas SELECT. Los ejercicios DML crean una tabla temporal aparte.

Compatibilidad: los ejercicios usan el dialecto de DuckDB. MySQL 8 sigue siendo el motor de los cuadernos de la asignatura; sus opciones de particionado, índices y JSON pueden tener otra sintaxis y comportamiento.

Los archivos locales y las consultas se procesan en tu navegador. Los cambios en tablas temporales se pierden al recargar la página o cambiar de base.
